# token-parity

Checks whether design tokens in Figma match tokens in code, and syncs drift in either direction.

## Layout
- packages/core: the engine and CLI (npm package). Never talks to Figma directly; reads and writes files only.
- skills/token-parity: the Claude Code skill. Bridges the engine and the Figma MCP.
- Distributed as a Claude Code plugin: .claude-plugin/{plugin,marketplace}.json at the repo root, with the
  engine bundled into skills/token-parity/bin/token-parity.mjs (pnpm build; committed; CI checks it's current).
  Keep the version the same in plugin.json, marketplace.json, packages/core/package.json and src/version.ts.
  The use_figma code it runs is generated by the engine (packages/core/src/figma-bridge.ts) and tested
  against a mock Figma; the skill never hand-writes Plugin API code.
- docs/kickoff-prompt.md: the original Phase 1 brief. docs/phase-2-design.md, docs/phase-3-design.md:
  plan/apply/commit and the skill.

## Commands
- pnpm test, pnpm build, pnpm typecheck (from the repo root)

## Decisions (do not change without asking)
- ESM only. Built with tsdown. Tested with Vitest. TypeScript strict.
- Test-first: write fixtures in packages/core/test/fixtures before logic.
- Pipeline: adapters -> normalize (DTCG-style) -> three-way compare (Figma, code, lock) -> report.
  check / plan / apply are separate commands. CI only runs check.
- Colors need 1:1 parity with Figma by default (`colorMatch: "exact"`): the same 8-bit sRGB value Figma
  shows, written in code as hex or rgb() so searching for Figma's value finds it. One 8-bit step is drift;
  the right color in another notation (oklch) is a format-mismatch. Exact needs an sRGB/legacy Figma file
  (Display P3 falls back to perceptual, with a warning). `colorMatch: "perceptual"` compares in OKLCH (ΔE)
  with near-matches for rounding. Never compare colors as strings.
- The format written into code is `colorFormat`: "preserve" (default: keep each value's format; new tokens
  use the file's usual one), "hex", "rgb", or "oklch" (perceptual only).
- Lock file stores the original OKLCH and the RGB last written to Figma. If Figma's RGB still
  matches the locked RGB, keep the locked OKLCH; never re-derive it.
- Out-of-gamut colors are warnings, not drift.
- Conflicts (both sides changed) are reported, never auto-resolved.
- The agent never edits token values by hand. All changes come from the engine.
